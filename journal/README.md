# Project Journal

Status: Chronological point-in-time history

Journal entries explain what happened during a dated work session, what changed, and why. They do not define the current lane merely because they are newer than an ADR, closure record, or status page.

## Reading Rule

1. Read the root `README.md` and `AGENT_CONTEXT.json` for current state.
2. Read the latest handoff named in `AGENT_CONTEXT.json` for the resume point.
3. Use journal entries to reconstruct decisions, experiments, and chronology.
4. If a journal conflicts with a current status surface, treat the journal as historical unless the current document explicitly incorporates it.

## Writing Rule

- Use `YYYY-MM-DD-topic.md` names.
- Record changed plans, stages, roadmaps, and specifications with the reason.
- Keep sandbox-local resume instructions in handoffs, not new sandbox journal files.
- Link the current journal from `AGENT_CONTEXT.json` at major pause points.
