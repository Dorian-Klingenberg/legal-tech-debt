# Stage 003: Design Tool Comparison

Status: Planned; blocked on Stage 002 human review

## Purpose

Test whether Figma, Canva, both, or neither improve a specific unresolved workbench design question after the local prototype has been reviewed.

## Entry Gate

- [ ] Stage 002 has been opened and reviewed visually.
- [ ] Desktop and narrow/mobile layout observations are recorded.
- [ ] One concrete design question is selected.
- [ ] The owner agrees the question is worth a time-boxed design-tool pass.

Do not run this stage merely because a design-tool account is available.

## Planned Comparison

- [ ] Give Figma the same sanitized content and question used for the HTML review.
- [ ] Give Canva the same sanitized content and question only if presentation polish is part of that question.
- [ ] Record time spent, useful changes, friction, and duplicate-truth risk.
- [ ] Compare each result with `output/workbench.html`.
- [ ] Summarize useful learning in repo-visible Markdown.
- [ ] Decide: keep Figma, keep Canva, keep both occasionally, or use neither.

## Outputs

- [ ] Completed rubric in `DESIGN-TOOL-EVALUATION.md` or a dated companion note.
- [ ] Links or export references only when they are useful and accessible.
- [ ] A concise recommendation for Stage 004.

## Boundaries

- Use sanitized/paraphrased evidence.
- Do not invent findings or product behavior.
- Do not make a design file the source of truth.
- Do not add hosted implementation or production infrastructure.

## Done When

- [ ] The chosen design question has a documented answer.
- [ ] Every accepted insight can be implemented or described from repo-visible records.
