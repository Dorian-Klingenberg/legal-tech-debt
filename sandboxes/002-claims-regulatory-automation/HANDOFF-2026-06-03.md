## Important Guardrails

- No final legal findings in Stage 002.
- Candidate evidence is allowed; detector findings are later.
- No semantic retrieval implementation until a tiny gold set and documented retrieval misses exist.
- No vector store selection until a follow-up ADR justifies it.
- No LLM use in the main Stage 002 pipeline.
- Any one-off LLM helper output must live in a non-standard artifact and must not mutate standard outputs.
- No reviewer annotations written back into Stage 002 substrate artifacts.
- No cross-document topic modeling or cluster-level graph edges in Stage 002.
- Every graph edge must have explicit text or structural evidence.

## Schema And ID Rules

Every JSON/JSONL record should carry:

- `schema_version`
- `run_id`
- `created_at`
- `source_hash` or `content_hash` where applicable

ID expectations:

- `source_id` stays stable when document identity does not change.
- `node_id` is deterministic under a fixed parsing and segmentation strategy.
- parser or segmentation changes that break node IDs require a schema/version bump, run-mode note, and migration notes.

Stage 003 should create versioned tiny retrieval gold sets under:

```text
data/goldsets/
```

Gold sets should use real snippets from Stage 002 outputs only.
